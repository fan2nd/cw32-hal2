# CW32L031 / CW32R031 / CW32W031 initial HAL backends

## Scope and organization

The three families share the audited `gpio_cw32l031_v1`,
`sysctrl_cw32l031_v1` and `flash_cw32l031_v1` register descriptions. The HAL
selects a shared GPIO backend with `gpio_cw32l031_v1`, and a shared HSI clock
backend with `rcc_l031_r031_w031`. Family cfgs only narrow the GPIO pad masks.
This is explicit register-version dispatch, not an F030 backend selected by a
similar-looking peripheral name.

Implemented: HSI-only `Config` / `init` / `try_init` / frozen clocks;
`Flex`, `Input`, `Output`, `OutputOpenDrain`; Embassy `Peri` ownership and the
embedded-hal 1.0 digital traits. Other peripheral drivers, including EXTI,
remain unavailable. Shared register layout alone does not prove complete
peripheral semantics, AF routes, DMA policy or interrupt behavior.

Features are the three family aliases and eight exact orderable parts:

- `cw32l031`: `cw32l031c8t6`, `cw32l031c8u6`, `cw32l031f8p6`,
  `cw32l031f8u6`, `cw32l031k8u6`, `cw32l031k8v6`
- `cw32r031`: `cw32r031c8u6`
- `cw32w031`: `cw32w031r8u6`

Family aliases expose the intersection of reviewed package pads. Exact-part
features expose their selected package's reviewed pads. The common public API
is retained wherever hardware supports it; these chips expose only
`Speed::Default`, because no software speed selection exists.

## Clock semantics and bounded handover

- HSIOSC is nominally 48 MHz. Read the factory calibration halfword at
  `0x0010_0a00`, applying only the 11-bit TRIM field. This is a different
  address from both F030 and F002/F003. An erased halfword fails before writes.
- Only the documented divider encodings are exposed:
  `/1=6`, `/2=8`, `/4=9`, `/6=5`, `/8=11`, `/10=12`, `/12=13`,
  `/14=14`, `/16=15`. The SDK's prose lists DIV3, but its constants and the
  manuals do not; the HAL does not manufacture that mode.
- HCLK divides SYSCLK by 1–128 (powers of two). A single PCLK divides HCLK by
  1–8. APBEN1/APBEN2 are gate-register banks, not separate PCLK domains.
- Valid incoming SYSCLK selectors are HSI=0, HSE=1, LSI=3, LSE=4. Selector 2
  is reserved, not a PLL. Undocumented selectors or HSI divider encodings
  fail before writes. All supported final clocks are at most 48 MHz.
- L031 datasheet V1.9 Table 7-4 limits HCLK/PCLK to 24 MHz at
  1.65 V ≤ VDD < 1.8 V and 48 MHz at VDD ≥ 1.8 V. R031 requires
  2.2–3.6 V; W031 requires at least 1.8 V in RF LDO mode (2 V in DCDC mode),
  with their buses rated through 48 MHz. The API does not measure board
  voltage, so the caller must select final clocks within those limits.
- Enable the unkeyed AHBEN.FLASH gate and check it, then set/read back
  FLASH.CR2.WAIT=2 before changing HSI trim or dividers. The manuals explicitly
  define this conservative setting through 72 MHz; this does not authorize
  operation beyond the device's 48 MHz limit.
- All three manuals §4.3.4 prohibit changing oscillator parameters after
  startup. The initializer enables LSI with its existing TRIM/WAITCYCLE,
  waits for stability and switches SYSCLK to LSI while preserving bus
  divisors. It verifies LSI selection before clearing HSIEN, then verifies
  both HSIEN=0 and HSI.STABLE=0 before any HSI parameter write.
- With HSI stopped, restore TRIM preserving DIV and set DIV preserving TRIM.
  Restart HSI and await STABLE. Install and verify the final bus divisors
  while SYSCLK is still LSI, then select HSI and verify the complete mux and
  divider setting. This prevents a transient overclock when final HCLK is
  lower than HSI. Restore LSI's entry software-enable state, checking that
  bit's readback if it was originally off. No physical LSI-stop status is
  required for successful HSI initialization. Only then reduce WAIT to 0 through 24 MHz or 1 through
  48 MHz. DSB/ISB barriers follow flash latency and clock-tree changes on ARM.
- LSI is only a temporary execution clock, so its frequency is not published
  and factory LSI trim need not be loaded. Its parameters are never written,
  including when it already supports RTC or clock detection. New
  bounded errors cover LSI start, temporary source switch, HSI stop and LSI
  software-enable restoration failures. A failed transition may leave the CPU on LSI; no frozen
  clocks are published. The polling budget remains iterations, not elapsed
  time; bootloader bus divisors also affect execution time during handover.
- Every hardware wait has a nonzero caller-configurable polling budget.
  Failed readbacks/timeouts publish no clock frequencies. A hardware failure
  consumes the initialization ownership set and may leave clocks partially
  changed; reset before retrying.
- SYSCTRL.CR0/CR1 and FLASH.CR2 writes supply KEY=0x5a5a in bits 31:16.
  Unrelated fields, HSE/LSE enables, LSELOCK and all clock-security controls
  are preserved. LSI's enable state is restored on success. Clock-fault
  auto-switching applies only when HSE or LSE is selected (§4.4.3.3), so it
  cannot reselect HSI while the verified temporary LSI source is selected.
  The backend does not reset peripherals or write debug/wakeup controls.
  FLASHWAIT is also documented as an alias in
  SYSCTRL.CR2; the HAL configures its FLASH.CR2 view only.
- There is no F030-style PLL, FLASH cache or prefetch configuration. HSE/LSE
  and low-power clock selection are not implemented, and no oscillator pins
  are configured by clock initialization.

The handover assumes a running device within its documented operating limits
and exclusive initialization ownership; it cannot repair an already unsafe
voltage, overclocked bootloader or failing external clock. Nominal frozen
frequencies are integer hertz, rounded down for fractional division; factory
oscillator tolerance and electrical limits still apply.

## GPIO semantics and pad restrictions

All four ports share one actual PAC block type. AFRL at +0x18 controls pins
0–7 and AFRH at +0x14 controls pins 8–15. Each AF field is four bits; ordinary
GPIO selects 0000. Only AF1–AF7 are documented, and no arbitrary AF API is
exposed in this initial backend.

No writes are made to reserved SPEED (+0x08), LOCK (+0x3c), HIGHIE (+0x2c),
or LOWIE (+0x30) offsets. Only rising/falling interrupt-enable bits exist.
Configuring a pin disconnects its output first, clears its own interrupt
enables and conflicting pulls, selects GPIO and its output type, and enables
output last. Output constructors preload the latch. Dropping a driver leaves
analog mode, no pulls, no output drive; the latch and neighboring pins remain
unchanged. BSRR/BRR/TOG implement isolated set/reset/toggle writes.

GPIOA/B/C/F clocks are unkeyed AHBEN bits 4/5/6/9. Clock enabling preserves
other gates, does not reset a shared port, and leaves SYSCTRL.CR2 untouched.
No SWD remapping or NRST change is performed.

Safe singleton pins exclude PA13/PA14 (SWD) and PF3/BOOT (input-only). NRST
is a separate pad. `AnyPin::steal` remains unsafe and package/board validation
remains the caller's responsibility, but its backend rejects input-only,
nonexistent and RF-internal pads. It permits SWD pads only under its explicit
special-function-remapping safety contract.

The accepted family-level external output-capable masks are:

| Family | A | B | C | F |
| --- | --- | --- | --- | --- |
| L031 | 0xffff | 0xffff | 0xe000 | 0x00c3 |
| R031 | 0xfff0 | 0xfcff | 0xe000 | 0x0003 |
| W031 | 0x7fff | 0xdf87 | 0xe000 | 0x00c3 |

R031 PA0–PA3 are internally bonded to RF SPI. W031 PB3–PB6/PB13 are internal
RF SPI/IRQ connections. They are deliberately unavailable to the generic GPIO
backend; adding an RF driver will require its own explicit ownership design.
RF subsystem pins named GPIO1/3/10/11 are not MCU GPIO bank names. Other pads
omitted by these masks are absent from the reviewed family package catalog.

## Verification

Register-backed tests use the generated PAC on aligned RAM and a clock
protocol model. They verify field offsets, reserved/neighbor preservation,
AF half selection, gate keys, divider encodings, every supported final clock
combination, bootloader entry sources, trim address, write order, bounded
waits, failure readbacks and refusal to publish a successful result on errors.
The clock model rejects parameter writes unless HSIEN and HSI.STABLE are clear
and SYSCLK is LSI, and rejects disabling whichever source currently clocks
the CPU. It injects rejection of each configuration write and separate
oscillator startup/stop failures. PAC-on-RAM tests explicitly simulate status
bit side effects; RAM alone cannot model oscillator stopping and restarting.
They do not simulate analog behavior or hardware latch side effects.

`tests/test_l031_r031_w031_hal_contracts.py` compiles each selected safe pad
and the public GPIO/RCC APIs on Cortex-M0+. It also checks expected compiler
errors for restricted/unbonded/RF pads, unsupported speeds, unported driver
modules and overlapping mutable pin borrows. `ci/check-hal.sh` discovers all
HAL features and runs host tests plus Cortex-M0+ release builds.

No firmware has been flashed or executed on L031/R031/W031 hardware. Electrical
GPIO behavior, oscillator startup/trim accuracy, clock-switch execution timing
and real flash fetch timing remain board-verification work.

### HSI-stop safety correction (2026-10-08)

A follow-up source audit found that the initial backend wrote HSI.TRIM while
HSI could still be running. Although the SDK follows that pattern, the explicit
prohibition in all three manuals §4.3.4 takes precedence. The old sequence and
its earlier 23-test matrix are superseded by the stopped-oscillator sequence
above. The public clock configuration and GPIO API are unchanged; initialization
now uses a temporary LSI source and can return the new bounded transition errors.

The corrected final sequence passed the complete integrated matrix:

- 27 host unit tests and 1 compile-fail doctest on each of all 11 family/package
  features: 297 unit-test and 11 doctest executions.
- All 11 Cortex-M0+ release library builds with `rt,defmt`.
- All 11 public GPIO/RCC API and safe-pad positive compilation controls, plus
  216 expected compile failures with their diagnostic reasons verified.

New full logs: [corrected host/release matrix](verification-logs/l031-r031-w031-hsi-stop-matrix.log)
and [revalidated API/package contracts](verification-logs/l031-r031-w031-hsi-stop-contracts.log).
These results supersede the earlier `l031-r031-w031-hal-matrix.log` result for
clock-sequence safety. No firmware was flashed or executed on hardware.

The added low-voltage transition test starts from a legal 8 MHz HSI boot
state and selects 48 MHz HSI with final AHB /2, /4 or /8. It verifies that
the final AHB/APB divisors are installed while SYSCLK remains LSI, before the
first return to HSI, preventing a transient 48 MHz CPU/bus clock.

The final LSI restoration checks the software LSIEN request only. It does not
require LSI.STABLE to clear, because physical stopping is unnecessary to prove
the final HSI tree. The test model deliberately leaves LSI status asserted to
verify this narrower contract. This is not a claim of automatic LSI consumers
on 031: unlike L010/L012, the reviewed 031 CR1 tables do not document that rule;
031 clock-fault detection explicitly requires software LSIEN, and 031 IWDT
uses dedicated RC10K. Those source distinctions are retained.
