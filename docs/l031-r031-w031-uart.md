# CW32L031 / CW32R031 / CW32W031 UART backend

## Supported scope

UART1, UART2 and UART3 reuse the established Embassy-style owned `Uart`,
`UartTx` and `UartRx` API, with blocking transfers and byte-interrupt-driven
async transfers. All three family aliases and their eight exact-part features
are covered. Actual constructors remain constrained by each package's safe
bonded routes. The `cw32l031` alias and `cw32l031f8p6` have no safe UART1
TX/RX route; `cw32l031f8u6` has UART1 RX only. The family alias offers
UART3 TX or RX on PA10, but no distinct-pin UART3 full-duplex pair. UART2
provides a safe full-duplex pair on every enabled feature. The implementation accepts eight payload bits with none/even/odd
parity, 1/1.5/2 stop bits, and PCLK-clocked 16/8/4-times oversampling. TX/RX
pins and interrupt bindings are instance-typed, and `split` / `split_ref`
retain the original ownership contracts. `embedded-io` 0.7 and
`embedded-io-async` 0.7 traits remain supported.

This is a source-verified port, not a claim of silicon validation. UART
register similarity does not enable other families or modes. In particular,
this audit does not enable L052/L083 UART, LIN, automatic baud detection,
UART timer/receive-timeout, low-power LSI/LSE reception, synchronous mode,
hardware flow control, single-wire mode, custom ninth-bit parity or DMA.

## Clock, reset and divider decisions

| Instance | Base | IRQ | Clock gate | Active-low reset |
| --- | --- | --- | --- | --- |
| UART1 | `0x40013800` | 27 | APBEN2 bit 9 | APBRST2 bit 9 |
| UART2 | `0x40004400` | 28 | APBEN1 bit 7 | APBRST1 bit 7 |
| UART3 | `0x40004800` | 29 | APBEN1 bit 8 | APBRST1 bit 8 |

APBEN2/APBEN1 are SYSCTRL offsets `0x34`/`0x38`; APBRST2/APBRST1 are
`0x44`/`0x48`. They are unkeyed, unlike SYSCTRL.CR0/CR1 clock-tree controls.
Masked writes preserve every unrelated gate/reset. Reset asserts zero and
releases one. Configuration enables the gate and reads it back before reset
and UART access. Dropping one split half preserves the other half's clock
and interrupt; the last drop disables them.

Both APB gate banks use the one frozen `pclk` frequency. Writing CR2 to zero
explicitly selects SOURCE=0, which all three manuals define as PCLK. It also
disables timer control, DMA requests, flow control, inversion, single-wire
mode and address matching. CR1 is initialized with LIN/synchronous/break
modes disabled, normal data polarity and falling-edge start detection.

The verified formulas are:

- 16-times: `PCLK / (16 * BRRI + BRRF)`
- 8-times: `PCLK / (8 * BRRI)`
- 4-times: `PCLK / (4 * BRRI)`

BRRI is 1–65535; BRRF is 0–15. A nonzero BRRF forces 16-times sampling,
so integer sampling modes always write BRRF=0. The maximum requested baud
is PCLK divided by the selected oversampling factor, reaching 12 Mbit/s
only at 48 MHz PCLK and 4-times sampling. This is a digital-divider ceiling,
not a guarantee of board-level signal integrity or oscillator tolerance.
The existing integer arithmetic rounds the combined 16-times divider before
splitting it, avoiding the SDK float path's BRRF=16 carry/truncation problem.
Zero baud, out-of-range dividers and excessive rounding error are rejected
before any peripheral or GPIO write.

## Essential register-version difference

The used CR1/CR2/IER/BRRI/BRRF/ISR/ICR/RDR/TDR offsets and ordinary event bits
agree with the older `uart_v1` backend, but `uart_cw32l031_v1` adds LIN,
auto-baud and timer fields. Its ICR reset word is `0x00000fff`, not `0xff`.

The clearable ICR fields are TC/RC/FE/PE/CTS at bits 1/2/3/4/6 plus
TIMOV/BAUD/RXBRK at bits 9/10/11. All are R1W0. Reserved bits 0/5/7/8
remain at their documented one-valued reset state; upper reserved bits
remain zero. Initialization clears every real status flag with `0x01a1`.
An ordinary TC acknowledgement writes `0x0ffd`; RC writes `0x0ffb`.
Those writes preserve the auxiliary status flags. Reusing `0xff` would
silently acknowledge unrelated events and write reserved bit 8 away from
its reset state. The old-family path still uses its original `0xff` word.
No read-modify-write is performed on ICR.

TC means one frame has completed. TXBUSY includes the shift register and
transmit buffer, so both blocking and async `flush` wait for TXBUSY=0.
A stale TC is cleared and completion is rechecked after interrupt arming.
The IRQ handler masks the relevant one-shot event group and wakes its task;
it neither reads RDR nor acknowledges RX status.

RC/FE/PE are bits 2/3/4. The task reads received data before acknowledging
only the observed RX flags, discards parity/framing-error data, and can
recover on the next frame. The hardware has no documented overrun flag.
New reception can overwrite RDR while software is late; the API therefore
continues to disclose possible silent data loss with slow IRQ/executor
service. There is no software RX buffer and blocking waits are unbounded.

Cancelling an async wait disables only that direction's interrupts and
leaves unread hardware status/data intact. Bytes already consumed or sent
form a completed prefix. No caller buffer pointer is stored in the ISR,
and no DMA engine is ever given a borrowed buffer. Dropping TX may truncate
queued bytes; callers requiring on-wire completion must flush first.

The audit also found an independent PAC source defect: TIMCNT at `+0x18`
is a 24-bit read-only count, although the vendor SVD marks it writable.
All three manuals §18.9.6 explicitly say `23:0 TIMCNT RO` (L031 printed
p354, R031/W031 p357). The driver never accesses or writes TIMCNT and keeps
TIMCR=0. The generator now applies the independently documented read-only
access correction, and the source-evidence test guards it.

## Verification

`embassy-cw32/src/usart/tests/mod.rs` retains the shared status/IRQ race,
flush, error recovery, divider, split-drop and cancellation tests. The
031-specific tests at `usart/tests_031/mod.rs` add exact 12-bit R1W0 words,
auxiliary-status preservation, all 27 parity/stop/oversampling combinations,
clock/register preservation, all three instance identities and baud ceilings
through 48 MHz. These are host models/PAC-on-RAM checks, not real hardware.

`tests/verify_l031_r031_w031_uart_sources.py` checks the pinned audit against
generated registers and all 11 chip metadata features. With
`--sources /path/to/cw32-sources`, it additionally checks original source
hashes, extracts all three PDF manuals, verifies the audited field semantics,
and compares normalized SDK operations.

`tests/test_l031_r031_w031_uart_contracts.py` compiles every enabled typed
TX/RX route and the actual blocking/async full/half constructors on
Cortex-M0+. It rejects wrong-instance pins/interrupt bindings, forbidden
pads, conflicting reborrows and premature receive-buffer reuse, checking
the intended compiler diagnostics. Positive controls run first. The
GPIO/serial AF audit separately verifies source tables and package filtering.

Verified on 2026-10-08:

- All 11 family/package features: 28 UART host tests each, 308 executions.
- All 11 Cortex-M0+ release builds with `rt,defmt`.
- All 11 compile-contract features: 360 typed route checks and 195 expected
  failures, with their diagnostic reasons checked.
- All three official manual/SDK source checks, including TIMCNT read-only
  access and normalized UART-source equivalence.
- The existing 21 UART tests also pass on F030, A030 and F020 (63
  baseline regression executions).

Full logs: [host/release matrix](verification-logs/l031-r031-w031-uart-matrix.log),
[typed compile contracts](verification-logs/l031-r031-w031-uart-contracts.log),
[official source audit](verification-logs/l031-r031-w031-uart-sources.log),
and [baseline regressions](verification-logs/l031-r031-w031-uart-baseline-regression.log).

No UART firmware has been flashed or executed on these chips. External
loopback, interrupt latency under load, RX overwrite behavior, cancellation
at real IRQ boundaries and baud accuracy remain hardware-validation work.
