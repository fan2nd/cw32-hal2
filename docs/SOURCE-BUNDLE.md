# Source-only bundle

This archive contains project source, curated hardware YAML, package metadata, the authored official-source catalog and lock under `sources/`, pinned acquisition and generation tools, documentation, and the authored provenance records needed to review redistribution. The source-reference subset also includes 11 unchanged SDK chip headers with explicit Apache-2.0 notices, the official Apache license and checksums under `sources/approved-sdk-members/`; `sources/SOURCES.md` maps YAML topics to the original documents and member paths. Generated chip JSON, PAC output, build reports, provenance views, intermediate verification receipts, toolchains, raw vendor downloads, compiler caches, logs and firmware binaries are excluded.

The complete original verification history remains in the project workspace. Historical receipt paths may refer to files outside this distribution. Their recorded hashes and measured results are preserved; omission is not a claim that those files can be regenerated byte-for-byte on every host. Immutable acceptance and replacement-provenance records required by the release guard remain included. Reproduce generated data, PAC files and checks with the README and `d` commands using the pinned toolchain and acquired official inputs.

`sources/evidence-sources.json` is the sole authored URL, revision, member and hash authority. Complete SDKs, SVDs, manuals and extracted text are acquired separately into ignored `sources/vendor/`. The 11 bundled headers are a narrow file-level exception, not permission to redistribute any complete SDK. Packaging verifies their exact delivery paths, source-lock hashes and sizes, retained Apache notices, checksums, and the unmodified official Apache license. Renamed or nested copies do not inherit this exception. Curated hardware facts live in `cw32-data/**/*.yaml` and cite canonical source IDs. `build/provenance/` and `build/reports/` contain reproducible local outputs and are absent from the bundle. Provenance generation bootstraps directly from the authored lock and YAML without requiring previous generated views or verification run receipts.

The omitted historical snapshot `docs/verification-logs/stage6/formatting/rust-before.tar.gz` contains the pre-rewrite `cw32-data-serde/src/lib.rs`, `cw32-data-macros/src/lib.rs` and `cw32-data-macros/tests/test_macros.rs`. Earlier exclusions of loose `before/` directories missed this compressed archive. Its exact archive and member hashes are recorded as `excluded_historical_unresolved` in `docs/upstream-file-provenance.json`. The local recovery copy is preserved. This correction does not establish redistribution permission for those predecessors or license clearance for previously delivered archives.

The release guard checks known exact prohibited vendor and predecessor hashes, including renamed files and nested ZIP, TAR, gzip, bzip2 and xz containers. It reads member bytes in memory and never extracts archive paths to the filesystem. Recognized containers with malformed or unsupported features fail closed, as does inspection exceeding eight container layers, 10,000 entries/streams, 64 MiB per input or expanded member (also the xz decoder memory cap), or 256 MiB of cumulative inspected archive content across the distribution. Expanded wrappers, complete TAR layers (including hidden metadata) and extracted member bytes each consume this shared byte budget. ZIP supports stored, deflate and bzip2 members; ZIP prefixes, unreferenced records, ZIP LZMA, ZIP64 end records and sparse TAR formats are rejected because they are outside this implementation's supported inspection bounds. Permitted project-authored archives within these limits remain eligible. These checks are limited to recorded content identities and provenance; they are not universal copyright scanning or legal clearance.

The source-only bundle keeps authored inputs separate from reproducible outputs. Source/provenance validation and generation do not depend on omitted historical logs or firmware binaries. No hardware execution is claimed.

The small `docs/electrical-metadata-equivalence.json` record is retained as a pinned historical audit input in `sources/evidence-sources.json`, not as a reproducible build report. It uniquely records the original before/after hashes, exhaustive voltage-domain comparison, ClockBounds identity and watchdog lifecycle correspondence. Current source alone cannot recreate that historical observation. Its bytes match the earlier accepted record; omitting it would break eight strict RTC provenance links. Ordinary generation logs, intermediate reports and binaries remain excluded.

`docs/flash-breadth-source-review.json` is likewise a pinned original-source review consumed by the authored electrical policy. It records official document identities/page evidence and the independent review boundary; it is retained as source provenance, not regenerated verification output.
