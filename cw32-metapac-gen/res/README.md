# cw32-metapac

Generated by the Rust `cw32-metapac-gen` adaptation of Embassy's
`stm32-metapac-gen`, using the pinned upstream `chiptool::generate::render`.
Normal generation reads the reviewed `cw32-data/registers` YAML. Regenerate
from the repository root with `./d gen-all`; vendor imports write separate
review candidates with `./d import-registers`.

Select exactly one chip feature. `cw32f030` is the generic die without a memory
size claim. C8/K8/F8/F6 features add datasheet-backed memory regions; they do not
resolve package bonding or alternate-function routes. `pac` is enabled by
default; `metadata` exposes `cw32_metapac::metadata::METADATA`; `rt` emits vector
tables and device.x for cortex-m-rt.

Register definitions originate from twelve official CW32 family SDK SVDs, each
pinned by archive and SVD SHA-256. The twelve family features cover source data
for F002/F003/F020/F030/L010/L011/L012/L031/L052/L083/R031/W031. A030 uses a separately documented shared-register-map profile supported by the
vendor CW32x030 reference manual, not an independent A030 SVD. All 37 catalog
parts have exact-name features with verified main Flash/SRAM and package
metadata; pin bonding and alternate-function routing remain unpopulated. This
is an imported PAC, not a silicon-validated promise of complete chip support.
Read `../cw32-data/README.md` for source pins, errata, and coverage limitations.
Register read-clear/write-one-clear effects and reset values are not modeled by
chiptool IR. Follow the vendor manual before using raw register writes.

## Raw-access safety boundary

As in the pinned chiptool generator, raw register operations use safe Rust
syntax but are technically unsafe hardware integration. They can cause undefined
behavior, including by programming DMA to access Rust-owned memory or bypassing
an active HAL driver's resource ownership. The PAC does not enforce ownership,
DMA quiescence, clock continuity or memory safety for arbitrary register writes.

When using the HAL, leave its owned DMA channel/configuration, interrupt flags,
triggers, shared controller reset and clock alone. Ownership persists through
forgotten transfers and error quarantine. Low-level takeover must independently
establish quiescence and preserve every other owner. The safe HAL copy path uses
an init-admitted capability; direct PAC access is an escape from that boundary,
not another ordinary safe HAL resource operation.
